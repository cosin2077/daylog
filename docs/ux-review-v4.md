## 估时规则与边界

1. 两个相邻截图观察都已识别任务且置信度有效：任务变化按间隔中点划分；中间只有一次匹配的应用切换时，以该事件定位边界。同任务则归到同一任务。
2. 邻图未识别时，只分配已识别一侧的半个间隔；存在明确应用边界时进一步裁剪，另一侧保留未知。锁屏、空闲、缺失、冲突及低置信标记不能被当成已识别任务。
3. 间隔受两个观察的 max_gap_seconds 和 300 秒硬上限共同约束；不外推到首张之前、末张之后，不跨不可用事件或未解释的应用往返。与已有区间做差，避免重复计时。
4. 推断单列，计入活动估计总量；最长连续段、任务连续性与切换明细中的连续观察时长不包含这种推断。推断是有假设的估计，不能叫精确工时或已证明的最小时长。
5. 新记录保存观察状态和估时版本。旧记录只在内存中恢复归档里的状态后计算；归档缺失、应用元数据不可靠或解释不足时保留原有不确定性。不重写历史 JSON，也不重跑模型或读取图片。
6. 保留原始语义解释；同任务关联仍依赖已有稳定 ID，不按标题猜测关联。合并后的活动数可能减少，today 和 report 使用同一合并结果；原分项可从 parts 追溯。

未采纳“把所有空白补成工作”“切换更多就是更差”“连续就是专注”，因为现有数据不能支持这些结论。低频采样仍会漏掉短动作，未识别的截图和不可用时段仍需留空。真实语义准确率与精确边界需要人工标注验证；本次回放验证的是规则、计数、边界及来源守恒。
