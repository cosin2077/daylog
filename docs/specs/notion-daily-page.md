# Notion 单日单页同步规格

实现基线：`ed996121f388fb5e6c6739c6680c0d34044e0269`。本次依据用户确认的简化结构，替换 0.10.0 双数据库同步，并完整完成验证、发布和本机升级。

- 一个 Daylog 数据库，每个日期一个页面；只有名称、日期、状态三个自动管理属性。具体活动按时间写入人类可读正文，保留事实描述、应用、动作、任务、估时区间及必要的不确定性，不生成效率或情绪评价、不上传截图、不增加模型请求。
- 手动 `notion sync` 默认配置时区的今天。省略日期时显示日期和时区并二次确认，默认拒绝；非交互输入必须显式 `--date YYYY-MM-DD` 或 `--yes`。显式日期直接执行；拒绝空日期和未来日期。`--dry-run` 默认今天，但不确认、不联网、不读凭证。
- 今天仍在进行，即使当前队列清空也标「待补齐」。午夜后自动同步前一天；开机/恢复联网/后台恢复后补传。日期及标题始终为原记录所属日期，按日历处理 DST。
- 同一日期的手动推送、午夜更新、迟到结果和重复推送更新同一页。后续更完整数据替换「Daylog 活动记录」区域，保留「我的备注」以及自动区域外的用户内容。用 API 定点更新而不是全页擦除；正文不完整或管理标题损坏时保留原内容并报错。
- 保留持久化锁、来源完整性保护、退避、Retry-After、权限/额度暂停及不确定创建回执。响应丢失时先核验，不能盲目创建重复页；本地来源批次被清理时不得缩减既有云端记录。合法分析修正可能减少片段数量，不能简单用条数判定更完整。
- 手动同步早于配置补传起点的日期，在后续自动调度中仍应补齐；空日期不建页。
- 旧双库配置可读但不再自动运行，必须显式 setup。已有单页库用 `setup --database <链接>` 复用，校验父页和三项字段类型，保留既有记录；不按同名盲目挪用其他库。不同目标数据库隔离同步状态和回执。旧库不因升级而被删除。
- 凭据继续保存在系统钥匙串/凭据管理器，保持原 AI 和用户配置。升级保留当前后台和暂停状态；真实验证只用受控合成内容，验收结束清理本次临时云端记录与本地资源。

验收覆盖：长正文（超过 100 个活动）、去重、手动今天到午夜、迟到结果、正文与个人备注保护、写入响应丢失、查询漏项、断网/限流/额度、来源缺失、旧配置提示、显式复用现有库、终端确认及非交互失败、完整 race 和相关平台 CI、签名发布及本机更新。实际午夜等待和真实屏幕/模型属于另外的验证边界，不用模拟结果替代。
