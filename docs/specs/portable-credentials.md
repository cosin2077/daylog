# 可迁移的 Notion 凭据

Notion Token 改为保存在 `~/.daylog/integrations/`：

- `credentials.enc`：版本化 JSON，每个具名凭据用 AES-256-GCM 加密，名称作为 AEAD 附加数据；文件不包含 Token 明文。
- `credentials.key`：32 字节随机密钥，和加密文件一起迁移。目录 `0700`，文件 `0600`，拒绝符号链接和组/其他用户可读权限。
- 读取和写入都通过私有锁串行化，临时文件同步后原子替换，避免并发 setup 与后台同步互相覆盖。
- 旧 macOS 钥匙串/Windows 凭据管理器条目只在本地加密文件不存在时作为迁移来源。先写加密文件并精确回读，再删除旧条目；写入或回读失败时旧条目保留。加密文件损坏时直接报错，不回退钥匙串或覆盖。
- `notion status` 只检查加密文件是否存在，不读取 Token、不触发钥匙串访问；首次使用 `notion check`/`sync` 或后台同步时执行迁移。

安全边界是明确的：密钥与密文位于同一数据目录，可阻止明文搜索、日志泄漏和普通备份工具直接暴露 Token，但不能抵御能以当前用户身份读取整个目录的恶意程序。用户要求换取可搬迁性和不再出现系统钥匙串弹窗，因此接受这一折中。

回归覆盖无明文落盘、文件权限、损坏拒绝、并发写入、符号链接拒绝、旧凭据先迁后删及迁移失败保留旧条目。
