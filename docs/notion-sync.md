# Notion 每日活动记录

一个 Daylog 数据库，每天一页，只有「名称」「日期」「状态」三个字段。具体活动按时间写在正文，供人类阅读和第三方 AI 自行分析；不上传截图，不增加视觉模型请求。

## 配置

在 Notion 创建普通父页面，给 API 连接授予该页的读取、插入和更新权限，然后运行：

```sh
daylog notion setup
```

Token 隐藏输入，只存 macOS 钥匙串或 Windows 凭据管理器，不写入配置或日志，也和 AI Key 分开。脚本使用 `--page <父页链接> --token-stdin` 从受保护的标准输入传递。

已有简化数据库时可显式指定，避免重复建库：

```sh
daylog notion setup --page <父页链接> --database <Daylog数据库链接>
```

会验证父页、唯一数据源及三个字段的类型，保留现有记录；不会按同名挪用其他库。若换了本地数据目录，旧日期缺少本机回执时不会被覆盖，需恢复原数据目录才能继续更新；新日期可以正常同步。首次配置保存固定 IANA 时区，无法自动识别时用 `--timezone Asia/Shanghai`。`--since YYYY-MM-DD` 指定自动补传起点，默认昨天，不默认上传全部历史。

0.10.0 双库配置需重新 setup；升级不删除旧库，也不继续向旧库写入。凭据、来源标识和补传起点在同一父页下保留。新结构、不同目标数据库各自隔离同步进度与回执，避免沿用旧库的完成状态。

## 手动同步与确认

```sh
daylog notion sync                       # 默认今天，先显示日期、时区并确认 [y/N]
daylog notion sync --date 2026-10-20     # 明确指定日期，直接执行
daylog notion sync --yes                 # 明确接受默认今天，不再询问
daylog notion sync --dry-run             # 默认今天；只导出本地内容，不联网、不读凭证、不询问
daylog notion status --json
daylog notion check
daylog notion disable
```

默认确认接受 y/yes/是，回车或其他输入取消，不读取凭据或发起同步。非交互环境必须显式 `--date` 或 `--yes`；`--json` 不代表同意，提示只写 stderr，stdout 保持 JSON。空日期和未来日期拒绝执行。

今天尚未结束，手动推送后状态为「待补齐」，并在正文说明只包含当前已有记录。无记录时不建空页。

确认后显示「正在同步到 Notion」加载动画，直到完成或失败；检查连接也显示进行提示。普通终端使用旋转指示，非终端输出一行静态提示，`--json` 完全关闭进度输出。提示写 stderr，结束或取消后清除动画。

## 正文和后续覆盖

标题固定为 `YYYY-MM-DD · Daylog`，不是推送执行日。正文的「Daylog 活动记录」区域包含日期、时区、整理状态、具体描述、动作、应用、任务、可得的估时区间和必要的不确定性。估时仍是估计；插值和邻接推断已包含在总估时中，不重复相加。单帧不编造持续时长，旧版范围单列，未观察空白不等于休息。

「我的备注」及自动记录区域以外的内容由你编辑。后续同步定点替换 Daylog 活动记录，保留备注；请把人工内容放在备注区域，不要改动两个管理标题。正文读取不完整或管理标题损坏时保留云端原文并报错。

同日期的手动推送、午夜同步、迟到分析和重复推送都更新原页面。完整数据覆盖此前的部分结果，不额外创建活动库或活动行。活动数量不是唯一的完整性指标：合法分析修正也可能减少重复片段；但本地来源批次被清理或丢失时会停止覆盖，避免把完整云端记录缩减。来源索引在请求发出前保存，因此写入已成功但响应丢失也受保护。

## 自动同步与恢复

保持 Daylog 后台运行；登录自动启动可用 `daylog start --login`。每天固定时区 00:00 后同步前一天；电脑或后台停机、系统休眠、断网会延后到恢复运行后补传。不会唤醒关机的电脑。日期按日历推进，支持夏令时。

默认每次最多处理4个变化日期；内容未变不重复更新正文。今天的手动记录在结束后重新核验并更新原页面，迟到分析也会补齐。手动推送过的旧日期，即使早于 `--since`，也会在保留窗口内被自动复查，不因此扩大其他历史日期的上传范围。

普通断网和服务错误自动退避；429/529 遵守 Retry-After。权限、Token、字段或工作区额度问题暂停写入，修正后 setup 或手动 sync 恢复。`--retry-uncertain` 只在人工确认远端没有对应记录后使用；响应丢失会先根据日期或已知页面 ID 核验，不盲目重复创建。

本地保留期限制可补传的数据；云端历史不会因本地到期而自动删除。同步不取代独立备份。停用后已发出的请求仍可能完成。

## 第三方读取和额度

API 固定 `Notion-Version: 2026-03-11`。先按「日期」查询 data source，再读取页面正文；`GET /v1/pages/{page_id}` 只有属性。可用 `GET /v1/pages/{page_id}/markdown` 读取完整 Markdown，检查 `truncated` 和 `unknown_block_ids`；也可读取 block children 并完整处理分页、子块。日期查询同样需检查分页与结果完整性。

每天一页不等于每天一个 Notion 区块，正文也占区块额度。单成员免费工作区当前不限页面/区块，多成员免费工作区有累计区块限制；本功能不上传附件或使用 Notion AI。收到 block_limit 后暂停，不能用删除重试绕过额度。很大的单日日志可能超出 API 单次正文限制，程序明确报错而不截断；以工作区实际套餐和官方当前规则为准。

## 验证边界

单元和 HTTP 夹具覆盖确认、日期/DST、手动到午夜、迟到覆盖、长正文、个人备注、响应丢失、去重、权限/额度、来源丢失与配置迁移。真实 Notion 验证只使用受控合成内容，完成后清理临时记录。合成调度推进不等同于实际等待午夜、休眠或真实桌面和模型验收。
