# CLI operations

Normal use is `daylog start`, `daylog today`, `daylog stop`, and `daylog update`. Run `daylog help --advanced` for the full interface. `--data` selects a private alternative data directory; the default is `~/.daylog`. The directory must have mode 0700. All stored files are local plain files with mode 0600, not application-encrypted.

## Simple lifecycle

`daylog`, `daylog -h` and `daylog --help` show help with no data initialization or migration. Data commands initialize missing configuration automatically. `start` checks app-owned Screen Recording access, opens System Settings if needed and waits up to two minutes for the grant, then prepares and starts the service. Repeated starts reuse a live process or resume a paused one; an old process with stale permission is restarted after access is restored. `stop` waits for evidence to be sealed, unloads the service and removes its startup registration. Repeated stops are safe. Neither command deletes history.

The old `~/Library/Application Support/Daylog` is moved into `~/.daylog` on first use. A running recorder is stopped before migration; existing recording/login intent is retained where appropriate. Both directories existing is a conflict, never an instruction to overwrite data. Explicit `--data DIR` opts out of default-path migration and is useful for isolated tests.

Result commands default to readable Chinese. Add `--json` for machine-readable results: version, init, config, doctor, permission, windows, agents, start/stop/status/pause/resume, pending, commit, analyze, today, report, update, auth and service operations. `run` is a foreground process, not a result query; `service install --dry-run` explicitly exports raw plist unless --json is given. `today` reads the diary without starting recording or model calls.

## Configuration

`daylog config` shows a readable overview with the key hidden; `daylog config --json` exports the complete configuration, potentially including the plaintext key. `config --endpoint URL --model MODEL --api-key KEY` updates only the supplied API fields and enables that API; other preferences are preserved. `config --agent auto` disables the direct API and returns to installed agents; `claude`, `codex` or `hermes` selects one adapter. `config --api-key KEY` saves the plaintext key as `ai.api_key`. `config --api-key-stdin` optionally stores a key in Keychain and clears the configured plaintext/environment sources. `config --key-env NAME` selects an inherited process environment variable (ordinary LaunchAgents do not automatically inherit terminal variables; plaintext JSON and Keychain both work in the background). `config -h` shows examples. You can also edit `~/.daylog/config.json` directly; keep other fields; `ai.api_key` accepts a plaintext key. To edit, save that full JSON to a private temporary file, modify the necessary fields, then `daylog config --file <file>` and remove the temporary file. Restart a running service to apply changes. Unknown fields are rejected. Key precedence is non-empty `ai.api_key`, then the configured environment variable, then Keychain. Selecting `--key-env` clears the old plaintext key.

- Default foreground/power polling: AC 30 seconds, battery 120, low-power mode 180.
- Actual capture is also bounded by `min_save_seconds` (default 90); high-frequency polling does not require screenshot encoding at every tick.
- Sampled RGB difference uses `change_threshold: 0.005` (0.5%) by default. The 32×18 point grid may entirely miss edits between sample points. v2 also checks local blocks, records repeated observations and takes a fresh image in each new batch; heartbeat_seconds is retained for old config compatibility, not used to save duplicate v2 images. Existing configuration retains its explicitly saved threshold across updates.
- JPEG height defaults to 720 and width is capped at 1920; quality 60. No cursor.
- `window_id: 0` captures the primary display. `daylog windows` lists window IDs and titles; titles may be sensitive. A selected window closing causes capture to pause, never fall back to full screen. Window IDs may change after an app restarts.
- `blocked_apps` contains bundle IDs, for example `com.agilebits.onepassword7`. Prefer the actual IDs on the machine. The capture excludes these apps, and a blocked foreground app suppresses capture entirely. Website-specific redaction is not implemented.
- Hardware idle >300 seconds suppresses capture. Reading without keyboard/mouse input may also count as idle; set `idle_after_seconds: 0` only when the user prefers completeness over that energy saving.
- Below 20% battery, lock, display sleep or serious thermal pressure: pause capture. No sleep-prevention assertions or power-settings changes.
- Batches default to 15 minutes and a target of four and at most eight selected screenshots (existing explicit limits remain in force). Raw processed images retain three days; pending evidence is protected. Raw cap 256 MiB, pending cap 96, text reports 90 days. At a limit, capture pauses rather than deleting pending evidence.

## API analysis

`agent.enabled` defaults true. `daylog agents` reports installation and adapter availability, never authentication success merely because a CLI exists. `agent.order` defaults to `claude`, `codex`, `hermes`; `agent.timeout_seconds` defaults to 180 (older explicit values are preserved). Disable agent analysis for capture-only use. Daylog searches PATH plus standard user/Homebrew bin directories so LaunchAgents find common installs. Unsupported flags, missing login, unavailable vision and invalid output fail the invocation, then eligible fallback is tried within the shared budget. Grok/Antigravity currently have no verified image adapter.

`agent.inherit_login_environment` defaults true. Before each CLI invocation, Daylog queries the user's existing zsh/bash interactive login environment (five-second limit) to supplement missing provider/model/authentication and proxy variables. Codex also imports credential variables explicitly declared by env_key under model_providers in its config.toml, including custom names outside OPENAI_. Explicit caller values win; unrelated profile variables are not imported. The query may execute normal shell startup code. This environment import does not persist credentials to Daylog files or logs. Set this field false to use only inherited process variables and the Agent's own configuration files. This addresses a real case where foreground Claude worked but LaunchAgent lacked the provider exports in `.zshrc`. Prompts and CLI arguments are never interpolated into the shell command.

Codex receives image attachments and a JSON Schema in read-only, ephemeral mode with shell/desktop/browser features disabled. Claude uses stdin image messages with builtin tools disabled and no session persistence. Hermes accepts one image, so a contact sheet ordered by position is created; small text may lose detail, and its session persistence remains governed by Hermes. Prompts and copied images are private temporary files removed after the child exits. No permission-bypass flags are used. Child groups are killed on timeout/cancellation. Existing provider configuration and auth are retained.

Supports a full OpenAI-compatible Chat Completions endpoint with image input. This does not require an OpenAI-owned service. Other protocols can be used through the active agent's vision tools and `commit`.

Set `ai.endpoint`, `ai.model` and `ai.enabled: true` only after the destination is selected. HTTPS is required except localhost/loopback for local models. Set the plaintext key with `daylog config --api-key KEY` or edit `ai.api_key` in JSON. System Keychain via stdin is an optional alternative. `DAYLOG_API_KEY` is supported for a foreground run, but LaunchAgents do not automatically inherit terminal environment variables.

The direct API request has a 60-second timeout and 1,800 output-token limit. Invalid or truncated JSON is rejected. No HTTP retry occurs inside one API attempt; failed rounds use exponential backoff from 15 minutes up to 6 hours, without permanently exhausting a batch. Fresh work gets priority. Explicit `analyze --batch ID --retry` clears cooldown eligibility but preserves counters and daily budgets; all invocations count toward the daily budget (`ai.max_requests_per_day`, 192). Agent-internal network retries are outside Daylog's accounting. Redirects are refused for screenshot API calls. Missing evidence, budget exhaustion and failed batches remain visible via `pending`.

By default automatic analysis waits for AC power. `analyze --batch ID --allow-battery` is an explicit one-off override; do not use it silently.

## Background service

On installed macOS apps, `doctor`, `windows` and `permission` use LaunchServices so their native queries have the background app's identity. A terminal-spawned process can have different Screen Recording access from the app. Use the installed CLI and verify `doctor`; a system-settings toggle alone is insufficient proof.

Normal users only need `start` and `stop`. For diagnosis, `service install` writes a scoped LaunchAgent but does not immediately load or run it. `service start` loads and starts it; `service stop` unloads it. `stop` also unloads and removes the service registration without deleting history. Add `service install --login` only for requested login startup. The service uses Background process type, nice +10 and low-priority I/O; screenshot work also uses Utility QoS. No keep-alive restart loop.

`service uninstall` removes only the service. Removing the app or skill also leaves data and Keychain credentials. Use `auth delete` only when credential removal is requested. There is intentionally no implicit full-history deletion operation.

## Updates

`daylog update --check` reports the current/available version for the running binary's platform; `daylog update` installs a newer one. The installer defaults to the GitHub latest regular Release feed, available once a regular release is published. Explicit `install-runtime.sh --source FILE` installs from a local build and remembers that path. Switch to a trusted HTTPS manifest with `update --source URL --remember --check`. Local manifests may reference sibling tar.gz filenames; HTTPS manifests may use absolute or relative package URLs. Schema: `{"version":"0.1.0","artifacts":{"darwin-arm64":{"url":"daylog-macos-arm64.tar.gz","sha256":"64 lowercase hex characters"}}}`; include `darwin-amd64` for Intel.

Packages are limited to 32 MiB compressed / 64 MiB expanded. Traversal, symlinks, hardlinks and special files are rejected. Code signature, bundle ID `io.daylog.agent`, version and native executable architecture are verified before stopping recording. This checks package integrity, not Developer ID notarization or a guarantee that a compromised feed is trustworthy. No scheduled update is installed. Data and credentials are retained. `--force` bypasses the version comparison and is only for controlled reinstall testing; ordinary updates do not downgrade. Current replacement uses two renames, not a single crash-safe transaction. Errors in the second rename trigger rollback, but process/power failure between renames can leave the app only in the staging directory. Failed service startup does not roll back the new app. There is no updater concurrency lock, signed manifest, pinned publisher yet; do not claim production-grade automatic update safety.

After updating, use `start` to check permission and resume. During diagnosis, `doctor` reports app-owned permission. In a real 0.1.0 to 0.1.1 ad-hoc update, the LaunchAgent restarted but Screen Recording access was lost despite the toggle still being on. If access is false, ask the user to refresh the Daylog entry in System Settings: remove the old entry, add `~/Applications/Daylog.app`, grant the same Screen Recording permission, and restart the service. Any OS authentication must be completed by the human. Do not modify or reset TCC databases.

## Period reports and screenshot folders

`report` writes a self-contained HTML and opens the default browser. `--no-open` only writes it; `--json` returns the selected period summary instead. `--period day|week|month` defaults day; `--date YYYY-MM-DD` selects the calendar anchor. Week starts Monday, month uses calendar boundaries, all in the machine's local timezone. The HTML includes all three views, pagination, search, category/date filtering and print styles. Coverage uses the union of clipped intervals, not summed overlapping work-hours. Pending, failed and active-draft evidence remains visible. No model is called during report generation.

HTML is written privately to `reports/report.html`, overwriting the previous snapshot. A cached HTML older than the configured text-retention period is cleaned up by generation time. New raw images use `frames/YYYY-MM-DD/<UTC-id>.jpg`; legacy flat images continue to work. Storage accounting and cleanup walk both layouts and preserve pending evidence. New date folders are 0700, images and HTML 0600.

`prompt` prints the shared analysis instructions without starting a recorder or model request. API requests add actual batch metadata and images; Agent adapters also prohibit tools. The LLM output schema remains the batch/card schema documented in report-format.md. Day/week/month summaries are local aggregations of those validated cards.

## v0.4 activity analysis

New batches use v2 interpretation output: no model timestamps. Read report-format.md before manual commits. Observations persist in the draft/batch plus dated observations/*.jsonl. Keyframes prioritize app boundaries; omitted frames are interpolated only between matching keyframe task labels within the support gap, with uninterrupted same-app samples. Interpolated time is marked separately; other gaps stay unknown. Context is bounded to five recent tasks within 30 minutes; task IDs are validated against the exact persisted context. Stable IDs permit task aggregation but do not establish semantic correctness.

Defaults: target_images_per_batch=4, max_images_per_batch=8, max_images_per_day=1536, max_observation_gap_seconds=300. Runtime continuity also requires an interval <= twice the mode's capture interval. Requests and submitted images include retries. Usage records distinguish known direct API tokens from unknown Agent usage. This is not a strict token/money budget.

`config --profile balanced|battery|detailed` changes sampling, batching and budgets only. It preserves model credentials, privacy choices and analyze_on_battery. Restart a running recorder to apply. `report --from RFC3339 --to RFC3339 [--json|--no-open]` handles a positive range up to 366 days, clips valid time spans and includes unknown/legacy indicators.

`daylog status` displays a Chinese status overview with local timestamps, uptime, capture/skip counts, pending batches and raw-image disk usage. Use `daylog status --json` for programmatic reads; its original status fields are preserved. Capture/skip counters cover the current process only; disk usage and pending batches include history. A running background process does not guarantee active capture or model analysis.

## v0.4.1 diagnostics and progress

Analysis request/response events are in `logs/llm/YYYY-MM-DD.jsonl` (rotation at ~1 MiB). The default diagnostics budget is 32 MiB, retention 7 days; fields are diagnostics.enabled/retention_days/max_bytes. Payloads contain the actual Daylog instructions, metadata and local image references, not Base64 or auth headers. API response bodies / CLI model results and bounded redacted stderr are retained. Treat these files as private: automatic redaction cannot classify every secret inside arbitrary natural-language output. Logs do not expose Agent-internal network payloads. Query only the relevant batch/request, never load the entire log directory into model context.

Agent effort defaults low and can be inherit/medium/high. Codex hooks/plugins/memory loading are disabled per call; Claude safe mode keeps auth/model selection while disabling customizations, with a minimal system prompt, low effort and a single turn; no forced structured-output tool round is required. structured_output is still parsed when provided. CLI settings and credentials are not rewritten. Current CLI flag support must be checked when troubleshooting older Agent versions.

Status reports analysis_state, analysis_error, failed_batches, last_analysis, next_retry and report freshness. Update/analyze spinners use stderr on a TTY; --json suppresses progress. HTML shows its snapshot age and a regeneration hint. The WindowServer frontmost normal-window owner is used for app metadata instead of a cached NSWorkspace value; special overlays, Spaces and focus without normal windows remain native-test boundaries.


API fallback is opt-in: `config --api-fallback --fallback-models MODEL2` uses the configured agent order first, then `ai.model` and `ai.fallback_models`. `--api-fallback=false` selects direct API mode; `--agent claude,hermes` selects only those agents and disables API until explicitly re-enabled. Every provider attempt shares the normal daily budgets; a fully failed chain is one failure round. Stop/cancellation, power pauses and exhausted budgets do not count as failed retries. A batch triggers one macOS notification submission after the initial failure plus six failed retries; the persisted marker prevents repeats after restart. Banner visibility depends on macOS notification settings. Status, pending and HTML keep visible failure/retry information regardless of banner delivery. The HTML retry button copies a command; a static page cannot execute local commands.

The report now has span-derived category/time charts and task rankings. Unknown/low-confidence/legacy model intervals are excluded from observation-time charts. Distribution buckets respect report-local time, and intersect actual observation spans rather than card bounding intervals. Day/week/month tabs, search, filters, pagination, evidence expansion and print/PDF work offline without third-party assets.

System failure banners are optional: `config --notifications=false` or `diagnostics.failure_notifications: false`. This does not disable retries, JSONL diagnostics or persistent status/report alerts. Restart the daemon to apply.


Fixed-signature release builds pin the public certificate in both installer and updater. The private identity belongs only on the maintainer/build host, never on a user's machine. Development packages require explicit local/loopback-only development opt-ins and cannot pass the public release packaging checks. Current reports include a calendar of day views for the snapshot, precise observation/unknown spans, app search and a table timeline; unknown spans are available through their own filter. Summary text reuses existing results and does not imply a separate daily LLM call.
